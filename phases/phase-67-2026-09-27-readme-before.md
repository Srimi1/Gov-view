# GOV View

Find government jobs, recruitment exams, licences and public admissions. Check whether you can apply, then go straight to the official notice.

GOV View is free and open source. The current static site uses no paid API, server, or database. Source collection and publication use reviewed pull requests. Free hosting and automation still have usage limits; deployment stops if the export exceeds project limits.

- **Eligibility checker.** It compares your details with each notice's rules: age on the notice's cut-off date, with category, disability and ex-serviceman relaxations; qualification and final-year status; nationality, including certificate-only cases; state domicile; attempts; and experience.
  - It answers three questions separately: *can I apply*, *can I sit the exam*, and *can I be appointed*.
  - It never says "yes" unless every rule in the notice has been captured.
  - Your details stay in your browser. They are never sent anywhere and never put in links.

## How the data gets in (free)

```
sources/registry.json → GitHub Actions (hourly, free on public repos) → connectors/* → pull request → you review & merge → site redeploys
```

## Run it

Use Node 26.

```bash
npm ci
npm run dev        # http://localhost:3000
npm test           # eligibility, dates, connectors, source coverage, merge rules, share links
npm run build      # static site in out/; hashes inline scripts and enforces free-host limits
npm run metrics    # collection, approval, review backlog, freshness and export budget
npm run collect -- --source in-upsc,in-ssc   # fetch live data (writes data/published/)
```

Optional environment variables are listed in `.env.example`.

## Publishing (free)

1. Push to a **public** GitHub repository.
2. Under Settings → Pages, set the source to **GitHub Actions**. The `deploy` workflow publishes on every push to `main`.
3. Under Settings → Actions → General, allow Actions to **create pull requests**, so the collector can open review PRs.
4. Optional: add the `USAJOBS_API_KEY` and `USAJOBS_EMAIL` secrets. A free key is available at https://developer.usajobs.gov/apirequest/.

GitHub Pages remains the active publishing workflow until a Cloudflare Pages project is connected and verified. GitHub Pages does not apply `public/_headers`; each exported HTML page carries a per-page hash Content Security Policy. Configure `NEXT_PUBLIC_SITE_ORIGIN` to the deployed origin and `NEXT_PUBLIC_SITE_URL` to the full deployed base URL when changing hosts, so canonical links, sitemap URLs and feeds point to the live site.

For the planned Cloudflare Pages Free cutover, connect this public repository using Git integration, set build command `npm run build`, output directory `out`, Node.js 26, and both site URL variables to the assigned `https://<project>.pages.dev` or custom HTTPS origin. Leave `NEXT_PUBLIC_BASE_PATH` empty for a root-hosted site. Check the deployed response with `curl -I`: Cloudflare must apply framing, MIME, referrer, and permissions headers from `public/_headers`. Keep the existing GitHub Pages deployment available as rollback until the Cloudflare site and links pass browser checks. No paid plan, Workers, Functions, database, or object store is required.

`scripts/secure-export.mjs` fails the build above 18,000 files, 20 MiB for any asset, or 750 MiB total. It also scans output for high-confidence credential patterns. CI runs pinned Gitleaks against repository history. These guards keep output below current [Cloudflare Pages Free limits](https://developers.cloudflare.com/pages/platform/limits/) of 20,000 files and 25 MiB per asset; monthly build and storage allowances still need checking before scale-up. No record data is silently dropped to fit the host; only optional static pages are capped.
